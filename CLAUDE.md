# Emberwake: guide for Claude

Read this first in a new chat. It's the context from the long first build session: what the game is, how the code fits together, how we work, and what's been decided.

## The project
- **Emberwake** is an original, first-person, Zelda-1-like adventure in the browser. Retro pixel raycaster, 1–4 player online co-op.
- **Owner: Mitch.** Dev names are MITCH and LOGAN (`DEV_NAMES` in `src/core/util.js`); only those names get debug mode. Repo: `MLMecham/emberwake`, hosted on GitHub Pages. Local copy on Mitch's PC: `C:\Users\mecha\outsidedrive\created_games\emberwake`.
- **Mitch pushes with git himself.** After every change, give him the commands:
  ```
  cd C:\Users\mecha\outsidedrive\created_games\emberwake
  git add -A
  git commit -m "..."
  git push
  ```
- **Docs:** `docs/IDEAS.md` is the backlog (things discussed but not built). When Mitch says "add a todo" or "for later", it goes there. `docs/ADDING_CONTENT.md` and `docs/templates/` explain adding enemies, items and elites. `docs/art/` is a GIF gallery of every sprite, regenerated by the build.

## How to work
- **Never edit `index.html` by hand.** It's the bundle. Edit `src/`, then run `python3 build.py`. File order is in `build_order.json`; folder globs pick up new files automatically.
- **Run `node tools/check.js` after every change.** It validates content and runs headless sim tests in a Node vm (add `--full` for 300 worlds). Add a test for each new mechanic, near the end of the `tests` string.
- **check.js also lints every source file for code hidden after a `//` comment on the same line.** That mistake froze the game once and broke the tides once. Put comments at the end of a line, never in the middle.
- **check.js does not run browser code** (render, input, net, ui; it only parses those). Smoke-test in a real browser before delivering. One bad `//` comment once commented out the movement line and froze the game. Playwright plus a headless Chromium works: start a new game, close the intro dialog (it pauses the sim), teleport with `G.sim.teleport(...)`, take screenshots, and watch for page errors. For co-op, run two browsers against a local PeerJS server.
- **Delivering:**
  1. Copy the changed files (including the rebuilt `index.html` and any new `docs/art` GIFs) to Mitch's folder.
  2. Check that the copies arrived intact.
  3. Tell him what changed in plain words, then give the push commands.
- **Working style:**
  - Mitch often sends sketches and asks "thoughts?". When he asks for ideas, give options with a recommendation and don't build until he picks. When he says "build" or "do it", build it.
  - Keep replies readable. Say what changed, then the push commands.
  - He likes screenshots of new visuals.

## Architecture (src/)
| Path | What |
|---|---|
| `core/` | util (rng, colors, constants like ARROWS_START, CANDLE_COOLDOWN), 5x7 pixel font (`~` draws ∞), content registry (`defineEnemy/Item/Sprite/SpriteVariant/Anim/Dungeon/Cave/Gimmick/Tile/Texture/Projectile`) |
| `engine/` | `tex.js` tiles, textures and themes; `spritekit.js` sprite building, hero sprites and armor overlays; `render.js` raycaster, viewmodel (hands/shield/sword/arms), HUD and maps; `audio.js` procedural sfx and music; `input.js` keys and gamepad |
| `game/world.js` | world generation: overworld regions, caves, dungeons from shapes, locks/keys, hidden rooms, gimmick hooks, `dungeonSolve`, tide/ice helpers |
| `game/sim.js` | host-authoritative simulation: players, enemies, projectiles, pickups, shops, rooms/groups, hazards, saves, snapshots |
| `content/` | everything data-like: enemies, items, elites, projectiles, drops, dungeons, caves, gimmicks, sprites, `ai.js` behaviors. Most files are scoped (their helper names can't clash). |
| `net/` | PeerJS co-op (`net.js`), ICE servers (`relay.js`) |
| `ui/main.js` | client loop, local movement prediction, events, menus (pause, inventory, debug), boot |
| `shell.html` | page markup and CSS (menus, inventory screen) |

**Model**
- The host runs `Sim` at a fixed step and sends each player a snapshot about every 50 ms. Clients predict their own movement and send actions (`sendAction({t:...})` → `Sim.onAction`).
- Tile changes go through `sim.setTile` → `mods`, which are sent to clients and saved. The exceptions are fast-changing tiles (tides, ice): see below.
- **Saves:** `SAVE_VERSION = 6`, with `migrateSave` in sim.js. When a dungeon layout changes, bump the version and reset that dungeon's progress.

## Systems and where they live
- **Map:** the map shows the compass room, the compass shows the map room, and with both a blinking `?` marks the dungeon treasure until you have it.
- **Frogs:** 1 in 10 spawns as a poison frog (never placed directly), and frogs never spawn in rooms with no water.
- **Dungeons:**
  - Each is drawn as a shape in `content/dungeons.js`. The generator builds a random tree, loops, locks and keys (keys always reachable), map, compass, and hidden rooms (`H`).
  - **Bramble Keep has no keys** (`noKeys`): every lock, and the way out of the entrance, is a cracked wall with a powder gourd in the room before it. Some rooms have a corner nook behind a cracked block with a prize (`gimmicks/cracked.js`). Gourds grow only where asked (`gourds: 'asked'`). Its tablet: "WE MELTED THE KEYS. WE DROPPED THE SKY. LET HIM DIG."
  - Optional fields on a dungeon: `itemSpots` (shape cells the treasure may sit in; the Sunken Stair's bow sits at a trident tip), `intro` (hand-built first rooms), `bossEye` (eye niche in the boss room), `secret: 'EYE'` (hidden room opened by a small eye), `loops`, `bombLoops`, `bossParty`, `bossDrop`.
  - Gimmick hooks: `room`, `doors`, `plan` (pre-pass with `solve(hasBow)`), `arena` (boss room), `update`, `level`.
- **The 12 dungeons:**

  |---|---|---|---|
  | 1 | Mossy Hollow | brambles | boomerang |
  | 2 | Bramble Keep | no keys: cracked walls, gourds, prize nooks | bomb bag (the boss-room eye niche holds the Big Quiver and the Loaded Shot scroll) |
  | 3 | Sunken Stair | tides, eyes and the spiral room | bow (boss: the Bog King) |
  | 4 | Emberforge | conveyors | fire rod |
  | 5 | Whispering Vault | fake walls | whistle |
  | 6 | Tideglass Halls | glass floors, glass-tutorial opening | raft (boss: spider) |
  | 7 | Iron Cathedral | statues | plate tunic (on a lake island; needs the raft) |

  | 9 | Hollow Crown | final dungeon | (Hollow King; only silver arrows finish him) |

  The optional frontier dungeons:

  The Hearth is behind the Hearthgate, which needs both relics.
- **Eyes and tides** (`content/gimmicks/eyes.js`, `drain.js`, `world.js` `tideCode`/`applyRig`, `sim.js` `updateRigs`/`hitEye`):
  - Only arrows and darts (`eyeHit`) shut eyes. A timed eye drains its room's tide (deep → drained → shallow → deep). A sealed eye opens something for good.
  - Tide state is sent as `snap.rg`, and every machine swaps its own tiles. Tide tiles are never written to `mods`.
- **Frost-arrow ice:** `freezeTile`/`thawTile` in world.js, `sim.freezeAlong`, synced as `snap.fz`. Fresh water only: tiles marked `salty` (the ocean) never freeze. Ice melts after 6 s.
- **Hazards:**
  - Walking enemies avoid lava, spikes and pits while walking. Knockback can push them in: pits and deep water kill them, lava, spikes and vents burn them. Fire creatures are immune to lava and vents.
  - Ice gives bigger knockback.
  - Flyers, ghosts and bosses ignore tiles. Swimmers (`def.swim`, the frogs) move through water and never drown.
- **Player status:** chill (slow), poison (5% of max health per tick, 2–5 ticks, restarts on a new dose, goes through shields, can't kill), Gale Cloak flight (`p.flyUntil`; tiles below don't affect you).
- **Controls:**
  - Click/Space: attack. Space is dash for the martial artist.
  - Shift is a modifier for both hands. Shift + attack (hold) = reverse grip (sword techniques). Shift + item = the item's technique (`useAlt`): bomb arrows, the wide boomerang throw.
  - Right-click/E: item. Hold for power: the bow fires on release; holding nocks one more arrow every 0.6 s (`LOAD_TIME`, one per Loaded Shot scroll).
  - Favorites (`favList` in main.js, stored in this browser only): star items in the inventory. Wheel and R step through favorites (all items if none), Q + wheel through everything, a tap of Q steps back, 1-4 pick the first four favorites.
  - I: inventory. M: map.
  - Attacking or switching items lets a drawn arrow go slack.
- **Inventory** (`renderBag` in main.js, `sim.equip`; three pages: GEAR, ITEMS, UPGRADES, no scrolling): wear any sword or tunic up to the best you've earned (`swordMax`/`armorMax`), pick plain or frost arrows, set the item button, and see upgrades and techniques.
- **Sword techniques** (sword hero only; `pommelStrike`, `chainHit`, `updateBackswing` in sim.js, reverse grip in main.js):
  - Pommel strike (everyone starts with it): Shift + hold attack, let go after 0.2 s. 0.25 damage, 2.5 s stun; a shield still blocks it from the front. Only it splits gourds.
  - Lunge (scroll `lunge`): hold the grip 1.5 s until it chimes, let go: dash forward and slash 2/3/4 times (wooden/white/magic+ sword). Stops at a foe and at the edge of pits, deep water and lava.
  - Heavy Pommel (scroll `heavypommel`): pommel strikes also strip armor, and disarm foes with `def.disarm` (knights lose their shield, wizards their staff): `disarmEnemy` tosses a `tossed` entity, then `def.disarmedSprite` and `def.disarmedAi` take over. Disarmed knights can't block and charge faster; disarmed wizards can't cast and blink away.
  - Armored foes (armor > 0) are never stunned by the pommel; the armor takes the blow.
  - Sword beams: other swords need full health, one at a time. The Dawnblade's beam flies at any health, up to 3 at once.
  - Every sword swing lands, even on a foe that was just hit (swings ignore the 0.35 s hit protection; projectiles don't).
  - Backswing: every third sword hit in a chain (hits under 2 s apart) readies a backswing. It fires on the first hit that leaves a foe standing (a kill saves it), cutting that foe again 0.14 s later.
- **Knights** (`enemies/knight.js`): the plain knight (blue shield, no sword: the one players learn on); the SWORD KNIGHT (dungeons 6-9) counts blocked hits (`shieldBlocked` in sim.js, `def.counter` = 2) and then winds up (`KNIGHT_WINDUP`, its blade glows) and cuts everyone in front; the ARMORED KNIGHT (armor 2, dark plate, red trim, red spiked shield, dungeons 8, 9, 12) and the CHAMPION (armor 3, black plate, horns, red great sword that cuts twice, `bigShield`: only a triple shot jars it; dungeons 9, 12). Plate comes off before the shield can be knocked away. Their look follows their armor (`lookFor`).
- **Armor** (`def.armor` 0-3, `e.armor`, `stripArmor` in sim.js): 25% less damage per level. Bombs (and bomb arrows) and the Heavy Pommel knock one level off with no damage, each only once per foe (`e.stripped`); a repeat just clanks. Armored skeletons `skeleton_a1..3` are debug-spawner only so far; their sprite loses greaves and gauntlets, then helmet, then breastplate.
- **Gourds and breakables** (`content/gourds.js`, `breakGourd`/`updateGourds` in sim.js, `placeGourds` in world.js): low props you walk over. Only a pommel strike (or a monk punch, marked TODO for his rework) splits one. Bramble Keep's powder gourds drop a bomb; coral, slag, bone piles and crystals elsewhere sometimes drop gems or a heart. They grow back 40 s later once nobody is within 6 tiles, and a save never keeps one broken.
- **Bombs:** carry 1 without a bag, 8 with the Bramble Keep bag, 16 with the Big Bomb Bag from the hidden grotto shop (`bombshop` cave). `bombCap` in sim.js.
- **Items of note:**
  - Quivers: 15 to start, Big Quiver 30, Great Quiver 50 (`quiver50`, debug only so far).
  - Loaded Shot: each scroll (`loadedshot`, `tripleshot`, any order) lets you nock one more arrow: 2 or 3 arrows for 2x or 3x damage and more knockback; against a shield it does one arrow's damage and makes the knight reel.
  - Arrow kinds: plain, frost or silver, picked in the inventory (`p.arrowType`). Only silver finishes the Hollow King.
  - Bomb arrows (scroll, debug only so far): Shift + bow costs an arrow and a bomb, bursts like a bomb, and seals a timed eye for good. Held as a loaded shot, every nocked arrow flies with the one bomb (`arrow2_bomb`, `arrow3_bomb`).
  - **Magic Wand** (`items/rod.js`, id still `rod`, Emberforge's treasure; it replaced the Fire Rod and the Thunder Rod). No magic meter: each bolt has a short cooldown. Its element is picked on the GEAR page (`p.wandEl`): plain FORCE BOLT (weak, shoves hard, short stun), fire (Flame Orb: fireball with burning ground), storm (Storm Orb: hops to 2 more foes).
  - Shift + wand casts the element's spell if you know it (separate scrolls): Force Wave, Flame Wall, Lightning Lance. A spell starts a 0.6 s chant (a `chant` entity, a ring at your feet), then fires. 7 s cooldown, shown as a bar under the B item.
  - **Casting together** (co-op only, needs the Tandem Casting scroll): a friend who starts the same spell within 6 tiles during your chant joins it, and it fires once, combined. Built so far: Force Wave x2-4 = GALE BURST (centered on the group, much wider, harder, longer stun, disarms knights and wizards). Joiners get their cooldown back. Fire and thunder combos and wizard pairs are in the backlog.
  - Boomerang drags loot and small keys back, and hooks a frog that's out of the water (or up for air), bringing it back dizzy (`dropCarried`, `e.carried`). A normal throw stuns for 3 s with a 0.25 chip. Hitting an already stunned foe only renews the stun (no damage). After 6 s of chained stun the foe gets a short immunity (`STUN_LOCK` in sim.js), so two boomerangs can't lock it forever. Bats still die in one hit (`boomerangKills`).
  - Boomerang upgrades (debug only so far, order: wide throw first, then the second): the WIDE THROW scroll (`widethrow`, Shift + boomerang) sweeps a curving arc that hits at sword strength with knockback, never stuns, and doesn't stop on a hit. The SECOND BOOMERANG (`boomerang2`) allows two out at once, and the wide throw becomes a mirrored pair of arcs.
  - Gale Cloak and Skeleton Key: built, given by debug, not placed in the world yet. Pressing the cloak again mid-flight drops you; with the Gale Slam scroll (`galeslam`) that drop stuns and shoves foes around you.
  - Candle: one flame every 2.5 s. Holding it (selected) lights dark rooms around you.
  - Raft: works outdoors only, never in dungeons.
- **Bosses leave a glowing WARP tile** (`sim.openWarp`) instead of throwing everyone out.
- **Death:** a downed friend can be helped up (hold F); markers show downed friends through walls. After 30 s you can respawn alone with Enter, which costs half your gems; they're left in a bag only you can pick up. No team-wipe penalty yet.
- **Shops:** check that you can carry the item, then 0.8 s between purchases.
- **Armor visuals** (`armorOverlay` in spritekit.js, `sleeveArmor` in render.js):
  - Chain: rings over the tunic color, on the chest, upper arms and both first-person arms.
  - Plate: steel with a tabard in the tunic color, a helmet with a plume, pauldrons, banded steel arms.

## Gotchas
- Solid props don't block their whole tile (`solidAt` in world.js, sizes in tex.js). Trees, pines and boulders block a diamond (`PROP_K`): side by side they're a wall, corner to corner you can slip between. Small props (`round: true`: bushes, cacti, graves, statues, signs, flames, torches) block a small circle (`PROP_ROUND_R`), so you can walk between two side by side. The hero's body is checked at 3x3 points (`BODY_PTS` in main.js) so nothing small slips between its corners. Wall tiles still block whole tiles.
- Explosions always land (`ignoreIframes`), even right after another hit, e.g. a bomb arrow's own arrow.
- Sprite pixels are unsigned (`Uint32Array`) but `c32()`/`rgb()` return signed ints. Compare with `c32(x) >>> 0`.
- Dead entities stay in `sim.ents` until the next tick. Tests that call `useItem` repeatedly should filter out dead projectiles first.
- The opening dialog pauses the sim. In browser tests, set `G.local.dialog = null` first.
- New snapshot fields go in `snapshotFor` (`me.*` for the player's own state). The client reads them from `G.snap`.
- When making something only some enemy types have, add a field to the enemy def (`swim`, `spawnAt`, `noElites`, `sprFor`, `onDamage`, `view`). Don't special-case ids in the sim.
- **Knights** are the only enemy with a back sprite (`def.backSprite`, picked per viewer in `sim.entView`) when you're more than ~120° behind them. No side sprites, on purpose: players learn about the back from an old man's hint (`defineHints` in knight.js).
- Snapshot entity tuples: `[id, sprite, x, y, scale, z, flags, price, bossHp, npcText, elite, isFoe]`.
- Underwater sprites are named `<enemy id>_sub` so the boss bar can find the name.

## Decisions already made (don't relitigate)
- **Elements:** frost belongs to arrows. Fire and lightning are for a future magic rod (the fire rod becomes a plain magic rod and scrolls add the elements).
- **Water:** the rough southern sea can't be rafted, and salt water can't be frozen. Overlap between the raft and frost arrows is fine.
- **The bow's role:** eye puzzles are bow-only on purpose. The Sunken Stair generator guarantees the bow is reachable without the bow (`dungeonSolve`).
- **Gauntlets** are a separate future item (strength), not part of plate.
- **The Sunken Stair spiral room** is one room in that dungeon only.
